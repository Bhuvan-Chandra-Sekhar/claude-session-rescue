# Contributing

Thanks for looking. This is a small, deliberately boring codebase and the aim is
to keep it that way.

## Ground rules

**1. Read-only is not negotiable.** The tool must never write into a Claude data
directory. Every write goes through `safety.open_for_write`, which refuses
targets inside `~/.claude`, inside the store being read, or inside that store's
parent. If you add a command that writes something, write through that function.
`test_the_store_is_never_modified` will catch you if you don't.

**2. Never commit real transcripts.** They contain private work — file contents,
credentials, client names, whatever was on screen. Tests use synthetic fixtures
generated by `tests/fixtures.py`. `.gitignore` blocks `*.jsonl` outside `tests/`
as a second line of defence. If you need a new shape to test against, add a
generator to `fixtures.py`.

**3. Stream, don't load.** Session files reach tens of megabytes. Anything that
does `json.load(open(path))` or builds a list of every record will be rejected.
Use `jsonl.iter_records`. Where reordering is needed, re-read the file rather
than buffering it.

**4. Malformed input is data, not an exception.** A user running this tool is
usually already having a bad day. Skip the bad line, count it, report it. The
only acceptable traceback is a bug in our own code.

**5. Standard library first.** There are currently zero runtime dependencies and
that is a feature: the tool installs anywhere Python does and cannot be broken by
someone else's release. A new dependency needs a justification in the README
saying what it earns.

**6. Don't hardcode anyone's machine.** No usernames, drive letters, home
directories, project names or session ids anywhere except clearly-labelled
examples in documentation. Assume the user is on a different OS from you, with
different projects, and has never read this repo.

**7. Derive, don't assume.** The slug rule was verified on exactly one machine.
Where the tool can read a fact out of the data instead of computing it from an
assumption — as it does with `cwd` — it should.

## Style

Clarity over cleverness. This is maintained by one person who needs to be able to
explain any line of it out loud. Prefer an explicit loop to a dense
comprehension; prefer a named function to a lambda; write comments that say *why*
rather than *what*.

Docstrings on modules and non-obvious functions, explaining the reasoning. The
comment `# uuid is not unique within a file, so key on line number too` is worth
more than any amount of type annotation.

## Running the tests

```bash
pip install -e ".[dev]"
pytest
```

Every behaviour claimed in the README should have a test. If you fix a bug, add
the failing case first.

CI (`.github/workflows/test.yml`) runs the suite on Python 3.9–3.13 across Linux,
macOS and Windows. Two claims get their own jobs, because they are the ones the
README leads with: `no-runtime-dependencies` fails if anything sneaks into
`dependencies`, and `read-only-invariant` runs the tests proving the session
store is never written to. Neither is allowed to go red.

The cross-platform matrix earns its keep here specifically: the slug rule was
only ever verified on Windows, and `docs/on-disk-format.md` marks the POSIX
behaviour as inferred. The macOS and Linux jobs are the first real test of that
inference.

## Reporting a problem with your own session store

Please don't paste transcripts into an issue. Run:

```bash
claude-session-rescue doctor --report report.json
```

That produces counts, version strings and field names only — no transcript text,
paths, project names or uuids. Attach that. If it does not contain enough to
diagnose your problem, say what is missing and we will add it to the report
rather than asking you for raw data.

## Things that would genuinely help

- A store from macOS or Linux, described via `doctor --report`, to confirm the
  slug rule generalises.
- A session with sub-agent records (`isSidechain: true`), which has never been
  exercised.
- A file with three or more message trees from real usage.
- Any record type currently listed as `[unknown]` in `docs/on-disk-format.md`,
  explained.
